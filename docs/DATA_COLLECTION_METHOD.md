# 数据采集与清洗方法

## 数据来源

数据来自高德地图 Web 服务 API，使用 Place Text、Place Polygon、Place Around 接口。坐标系采用高德 GCJ-02，经纬度顺序为 `lon,lat`。

采集脚本：`scripts/collect_dongqian_poi.py`

## 位置验证

采集前使用关键词定位验证研究对象：

- `嵊州老城·东前街`
- `东前街`
- `东前街地下停车场`

验证结果显示，东前街商业街、道路名、地下停车场、出入口、餐饮和管理中心等 POI 均落在研究区附近，可作为课程研究的空间锚点。

## 范围设置

核心区 polygon：

```text
120.821971,29.587232|120.822111,29.58672|120.823303,29.58698|120.823511,29.586596|120.82545,29.587243|120.825447,29.588404|120.821971,29.587232
```

脚本检查该 polygon 闭合、无明显自交，面积约 3.46 公顷。

圈层：

- `core_polygon`：高德 polygon 搜索。
- `buffer_500m`：以 `120.823632,29.587196` 为中心、500m 半径 around 搜索。
- `buffer_1000m`：以同一中心点、1000m 半径 around 搜索。

## 分页与补采策略

高德 POI 接口存在分页和可返回数量限制，因此脚本不只做关键词搜索，而是按功能分类系统采集：

1. 对每个圈层和每个 typecode 发起查询。
2. 每页使用 `offset=25`，并设置 `extensions=all`。
3. 对返回量接近接口上限的类型，在 500m 和 1000m 圈层中生成规则网格点进行补充 around 搜索。
4. 网格补采结果再按中心点距离过滤，确保回到对应圈层内。
5. 所有结果合并后按 POI ID 去重。

## 清洗规则

- 解析高德 `location` 字段为 `lon`、`lat`。
- 坐标不可解析的记录保留在 CSV，但不写入 GeoJSON。
- 优先按 `id` 去重。
- 缺失 `id` 时使用 `name + lon + lat + typecode` 作为去重键。
- 一个 POI 命中多个圈层时，`range_level` 保留最小圈层。
- 同时写入 `in_core_polygon`、`in_buffer_500m`、`in_buffer_1000m` 作为布尔归属字段。
- 多类型 POI 保留高德原始 `type` / `typecode`，另派生 `main_category` 用于统计和制图。

## 质量校验

已完成的校验包括：

- API 连通性返回 `status=1`。
- 清洗总表为 2810 条。
- `poi_cleaned.geojson` 可被 GIS 软件读取。
- `poi_summary_by_type.csv` 和 `poi_summary_by_range.csv` 与 `poi_cleaned.csv` 派生统计一致。
- `poi_visual_data.json` 中 POI 记录数为 2810。

## 重要限制

本数据是高德地图可检索 POI 样本，不代表全量设施底账。不同时间、关键词和高德数据更新状态可能导致结果变化。
